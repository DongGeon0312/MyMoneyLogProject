# 머니로그(MoneyLog) 요구사항 정의서
- 작성자: (이동건)
- 작성일: 2026-07-22
- 프로젝트 기간: 5일
## 0. 개요
가게부 웹서비스. 회원가입,로그인한 사용자가 수입과 지출을 기록하고 카테고리,월별 통계를 확인한다.

## 1. 유저 스토리

| ID | 유저 스토리 | 연결 기능 |
|----|------------|----------|
| US-1 | 사용자로서 나는 이메일과 비밀번호로 회원가입/로그인하고 싶다, 왜냐하면 내 가계부를 나만 보고 싶기 때문이다. | F-01 |
| US-2 | 사용자로서 나는 수입과 지출을 등록하고 싶다, 왜냐하면 돈이 어디서 들어오고 나가는지 기록해야 하기 때문이다. | F-03 |
| US-3 | 사용자로서 나는 등록한 거래를 수정·삭제하고 싶다, 왜냐하면 금액이나 날짜를 잘못 입력할 수 있기 때문이다. | F-03 |
| US-4 | 사용자로서 나는 거래를 식비·교통 같은 카테고리로 분류하고 싶다, 왜냐하면 어디에 돈을 많이 쓰는지 알고 싶기 때문이다. | F-02 |
| US-5 | 사용자로서 나는 이번 달 총수입·총지출·잔액을 보고 싶다, 왜냐하면 한 달 예산 상태를 한눈에 파악하고 싶기 때문이다. | F-05 |
| US-6 | 사용자로서 나는 내 데이터에만 접근하고 싶다, 왜냐하면 남이 내 가계부를 보거나 고치면 안 되기 때문이다. | F-06 |

## 2. 기능 명세 (MoSCoW)

| ID | 기능 | 설명 | 우선순위 |
|----|------|------|---------|
| F-01 | 회원가입/로그인 | 이메일·비밀번호로 가입, 로그인 시 JWT(accessToken) 발급, 비밀번호는 BCrypt 저장 | Must |
| F-02 | 카테고리 관리 | 가입 시 기본 카테고리 시드(지출: 식비/교통/주거/문화, 수입: 급여/용돈) + 추가·수정·삭제 | Must |
| F-03 | 거래내역 CRUD | 수입/지출 등록·조회·수정·삭제 | Must |
| F-04 | 목록 조회 | 이번 달 거래 목록 조회 (타입/카테고리 필터·페이징은 여유 시) | Must |
| F-05 | 월별 통계 | 이번 달 총수입·총지출·잔액 (카테고리별 집계는 여유 시) | Must |
| F-06 | 인가(본인 데이터) | 모든 조회·수정·삭제는 로그인 사용자(user_id) 기준으로만 허용 | Must |
| F-07 | 입력 검증 | amount>0, transactionDate 필수 등 Bean Validation (전역 예외 응답 통일은 여유 시) | Must |
| F-08 | 프론트 화면(필수 2종) | 로그인, 거래내역 목록+등록 (월별 통계 화면은 여유 시) | Must |
| F-09 | Swagger 문서화 | springdoc-openapi로 API 문서 자동 제공 | Should |
| F-10 | 배포 | Docker 컨테이너화 + GitHub Actions CI/CD + AWS EC2 실접속 URL | Must |

## 3. 비기능 요구사항

| 분류 | 요구사항 | 구체적 기준 |
|------|---------|------------|
| 보안 | 본인 데이터만 접근 | 모든 조회/수정/삭제 쿼리는 `user_id = 로그인 사용자` 조건 필수 |
| 보안 | 비밀번호 보호 | BCrypt 해시로 저장, 평문 저장 금지 |
| 보안 | 인증 방식 | `Authorization: Bearer {accessToken}` JWT 검증 |
| 성능 | 목록 페이징 | 거래내역 목록은 page/size 페이징으로 조회 (전체 로딩 금지) |
| 성능 | 통계 응답 | 월별 통계는 DB 집계 쿼리로 계산 |
| 검증 | 입력 유효성 | amount > 0, transactionDate 필수, type은 INCOME/EXPENSE만 허용 |
| 품질 | 일관된 에러 응답 | `{success:false, code, message, data:null}` 형태로 통일 |
| 배포 | 실제 배포·접속 | AWS EC2에 배포하여 실제 접속 가능한 URL 제공 |

## 4. 범위(Scope)

| 구분 | 기본 범위 (In Scope) | 확장 범위 (Stretch) | 이번엔 안 함 (Out of Scope) |
|------|--------------------------|------------------------------------------|----------------------------|
| 인증 | 이메일 회원가입/로그인, JWT 발급 | Refresh Token 재발급 | 이메일 인증, 비밀번호 찾기, 소셜 로그인 |
| 거래 | 수입/지출 CRUD, 월별 목록 조회 | 타입/카테고리 필터+페이징, 키워드/기간/금액 검색, CSV 내보내기 | 반복 거래, 첨부 영수증 이미지 |
| 통계 | 월별 총수입·총지출·잔액 | 카테고리별 지출 집계, 파이/라인 차트 시각화 | 연간 리포트, 카테고리 예측 |
| 프론트 | 화면 2종(로그인/목록+등록) | 월별 통계 화면 | 반응형·모바일 앱, 다크모드 |
| 배포 | Docker + GitHub Actions + EC2 | Jenkins, Kubernetes, 무중단 배포 | 오토스케일링, 멀티리전 |

## 5. 진행 원칙

- 필수 기능(F-01~F-10)을 100% 완료하고 EC2 배포까지 마친 뒤에만 확장(도전) 기능에 착수한다.
- "모든 기능을 30%씩"이 아니라 "필수 기능을 100%씩" — 얇더라도 끝까지 동작하고 배포된 결과를 우선한다.
- 일정이 빠듯할 경우 범위를 줄이는 순서: ① 확장 기능 제거 → ② 프론트를 필수 2종으로 축소 → ③ 통계는 총수입/총지출/잔액 등 핵심만 → ④ 필터/페이징 단순화. 단, 인증·인가와 배포는 마지막까지 지킨다.
